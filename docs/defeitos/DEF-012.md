## Passos para reproduzir

1. Criar uma reserva futura na sala A101.
2. Como ADMIN, `PATCH /api/salas/{id}/ativa?valor=false`.

## Resultado esperado

200, com a lista das reservas futuras que continuam marcadas para o recurso inativo.

## Resultado obtido

200 só com o cadastro; o administrador não fica sabendo das reservas afetadas.

## Causa

`definirAtiva`/`definirAtivo` só mudavam o campo.

## Correção

A desativação continua aceita, mas sala, professor e material devolvem `reservasAfetadas` (ids das reservas futuras que ocupam a agenda), como o bloqueio de manutenção já fazia. O recurso é travado durante a desativação. No front, a mensagem vira um aviso com a quantidade de reservas.

## Verificação

Teste(s): `ReservasAfetadasApiIT.desativarListaReservasAfetadas`, `desativarSemReservas`; `mensagem.service.spec.ts` (Vitest).
